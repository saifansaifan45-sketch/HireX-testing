1. Database Overview & Migration History
HireX uses PostgreSQL 15+ managed through Prisma ORM (v5+). The database schema contains 25
models and 13 enums.
Historical Migrations ( hirex-Backend/prisma/migrations )
1. init : Initial multi-tenant schema with Company, User, Recruiter, Candidate, Job, Application.
2. 20261007_schedular_interview_columns : Added hostJoinUrl  and candidateJoinUrl  to
interviews  table.
3. jr_missing_fields : Added resume snapshot and explicitly enforced Application.resume
onDelete SetNull .
4. 20261023_prd_gap_closure :
Added ApplicationStatus.DOCUMENT_VERIFICATION
Added OfferStatus.DRAFT , OfferStatus.EXPIRED
Added Recommendation.LEANING_HIRE
Added InterviewFeedback.culturalFitScore
Added multi-file DocumentFile  table and document audit stamps ( verifiedAt , verifiedBy ,
rejectionReason )
Added Interviewer.sharePhotoWithCandidates

3. Core Models & Field Catalog
3.1 Company (Tenant Root)
model Company {
  id                      String      @id @default(uuid())
  name                    String
  slug                    String      @unique
  logoUrl                 String?
  website                 String?
  industry                String?
  location                String?
  companySize             String?
  about                   String?
  careerPageCustomDomain  String?     @unique // CNAME custom domain
  careerPagePublished     Boolean     @default(true)
  createdAt               DateTime    @default(now())
  updatedAt               DateTime    @updatedAt
  recruiters              Recruiter[]
  jobs                    Job[]
  candidates              Candidate[]
  applications            Application[]
}

  sessions      Session[]
  recruiter     Recruiter?

model Job {
  id              String            @id @default(uuid())
  companyId       String
  recruiterId     String

  applicationForm ApplicationForm?

  id          String               @id @default(uuid())

  createdAt   DateTime             @default(now())
  job         Job                  @relation(fields: [jobId], references: [id], onDelete: 
Cascade)
  sections    ApplicationSection[]
}

4. Key Constraints, Indexes & Integrity Rules
1. Multi-Tenant Composite Keys: Candidate  enforces unique compound constraint
@@unique([userId, companyId])  ensuring candidate profiles are scoped per tenant.
2. Cascade Deletions:
Deleting a Job  cascades to ApplicationForm , ApplicationSection , and
ApplicationQuestion .
Deleting a Document  cascades to child DocumentFile  records.
Deleting an Interview  cascades to InterviewSlot  records.
3. SetNull Protection: Application.resume  enforces onDelete: SetNull  preventing candidate
account deletion from crashing historical job application records.
4. Performance Indexes:
Company.slug  (B-tree unique index)
Company.careerPageCustomDomain  (B-tree unique index for CNAME resolution)
User.email  (B-tree unique index)
Verification.value  (B-tree index for invite token lookup)
